# ТЗ: CopyrightRadar, версия self-host v0.1

Статус: черновик от 24.11.2026. Лицензия: AGPL-3.0-only (решено 24.11.2026). Имя: CopyrightRadar, пакет и папка `copyright-radar` (решено 24.11.2026). Публикация ещё не решена.

> **Оценка риска — не юридическая консультация.** Сервис показывает признаки риска по данным Meta и сервиса распознавания музыки. Решение об удалении поста и ответ на претензию — дело студии и её юриста. Эта пометка стоит в README, в интерфейсе (подвал каждой страницы и карточка поста) и в каждом экспорте.

## 1. Что это и зачем

Сервис проверяет музыку в Instagram Reels студии (салон, клиника, малый бизнес) на риск претензий по авторским правам.

Повод: фирмы-«охотники» находят коммерческие треки в Reels компаний и требуют тысячи евро за один трек. Встроенная проверка Meta ловит не всё: часть старых видео она не проверяла, а часть коммерческих треков пропускает.

Сервис делает 4 вещи:
1. Читает список постов аккаунта и отметки Meta об авторских правах.
2. Распознаёт музыку по звуку через ACRCloud (сервис распознавания музыки по «отпечатку» звука).
3. Ставит каждому Reel уровень риска по настраиваемым правилам и пишет причину.
4. Показывает ленту сеткой, как в Instagram, и даёт человеку отметить результат прослушивания.

Сервис **только читает** Instagram: все запросы к Meta — GET. Он не публикует, не архивирует и не удаляет посты. Убирает пост человек в приложении Instagram.

## 2. Пользователи

| Роль | Кто | Что делает |
|---|---|---|
| Администратор студии | владелец или маркетолог | ставит сервис, проходит мастер настройки, вводит ключи |
| Проверяющий | сотрудник, маркетолог | смотрит сетку, слушает спорные Reels, ставит ручную отметку |
| Юрист студии | внешний | получает экспорт (CSV, позже PDF); в сервис не входит |

В v0.1 один аккаунт Instagram на установку и один пароль входа в интерфейс. Роли «администратор» и «проверяющий» в v0.1 — одна учётная запись.

## 3. Поток данных

```
Instagram (graph.instagram.com, только GET)
   │  1. список media + permalink, thumbnail_url, timestamp, media_product_type
   │  2. copyright_check_information (если поле доступно, см. п. 6)
   │  3. media_url (только если Meta его отдала)
   ▼
Сервис (Docker, у студии)
   │  4. ffmpeg режет звук на фрагменты по 15 с
   ▼
ACRCloud (ключ студии)  ── 5. результат: трек, исполнитель, лейбл, ISRC, score
   ▼
Сервис: 6. правила риска → уровень + причины → SQLite
   ▼
Интерфейс: сетка, вкладки «В ленте» / «Архив», карточка, ручная отметка, экспорт CSV
```

Второй источник звука — **выгрузка Instagram** («Скачать информацию», ZIP-архив). Он нужен, потому что Meta не отдаёт `media_url` у видео с отметкой об авторских правах, а это самые рискованные Reels. Сервис сопоставляет файлы выгрузки с постами по дате и длительности; спорные пары подтверждает человек. Третий источник — ручная загрузка одного файла в карточке поста.

Если звука нет ни из одного источника, пост получает состояние «звук недоступен» и уровень по одним данным Meta.

## 4. Стек

Python 3.12, FastAPI, SQLite, httpx, Jinja2, ffmpeg в одном Docker-образе. Причина: ffmpeg и работа со звуком на Python проще всего, SQLite не требует отдельного сервера, и студия запускает всё одной командой.

Запуск: `git clone …` и `docker compose up -d --build`. Без `.env` и без своего файла правил сервис стартует: ключ шифрования создаётся в `data/`, правила берутся из `config/risk_rules.example.toml`.

## 5. Модель данных (SQLite)

| Таблица | Поля (главные) | Зачем |
|---|---|---|
| `account` | ig_user_id, username, account_type, connected_at | один аккаунт на установку |
| `secret` | name, ciphertext, created_at, expires_at | токен Instagram и ключ ACRCloud в зашифрованном виде |
| `media` | id, permalink, shortcode, media_type, media_product_type, timestamp, caption_excerpt, thumbnail_path | пост; превью хранится локально, ссылки CDN Meta истекают |
| `presence` | media_id, state (`in_feed` / `missing` / `archived_manual`), since, sync_run_id | «В ленте» или «Архив» и с какой даты |
| `sync_run` | id, started_at, finished_at, fetched_count, complete, outcome, missing_ratio, confirmed_by | журнал кнопки «Актуализировать» |
| `meta_check` | media_id, status, matches_json, raw_json, fetched_at | ответ Meta как есть плюс разбор |
| `audio_source` | media_id, kind (`api` / `export` / `upload`), file_path, duration_s, has_audio_stream | откуда звук |
| `recognition` | media_id, provider, segment_start_s, status, track, artists, label, isrc, score, raw_json | по строке на фрагмент |
| `assessment` | media_id, level, reasons_json, rules_version, assessed_at | итог правил; старые оценки не удаляются |
| `manual_review` | media_id, verdict, note, reviewer, reviewed_at | ручное прослушивание |
| `audit_log` | at, actor, action, details | кто что сделал в сервисе |

Дату архивации Meta не отдаёт ни в API, ни в выгрузке. Поэтому `presence.since` — это дата проверки, на которой пост пропал из списка. Интерфейс так и пишет: «не найден в ленте при проверке 24.11.2026».

## 6. Ограничения Meta (факты)

1. Список постов: `GET /{ig-user-id}/media` с полями `permalink,media_type,timestamp,thumbnail_url,media_product_type`.
2. У видео есть поле `copyright_check_information`: `status` (`complete`, `not_started`, `in_progress`, `error`) и `matches` с автором и `owner_copyright_policy` (например, «Facebook Sound Collection»). Реальный ответ API расходится с документацией (`complete` вместо `completed`, действие `TRACK`, сегменты с ISRC). Разбор должен принимать неизвестные значения и хранить сырой ответ.
3. **Открытый вопрос № 1.** Первая проверка на реальном аккаунте шла через Instagram API with Facebook Login. Для Instagram API with Instagram Login справочник Meta не ставит ограничения на это поле, но прямого подтверждения нет. Мастер настройки делает пробный запрос этого поля. Если поле не пришло, сервис работает без сигнала Meta и пишет об этом в интерфейсе.
4. Статус Meta «совпадений нет» — слабая гарантия. Meta не проверила часть старых видео и пропустила коммерческие треки. **Правило: отсутствие совпадений у Meta никогда не понижает риск.**
5. Проверку Meta нельзя запустить через GET. Видео в `not_started` остаётся таким.
6. У видео с авторской музыкой или отметкой Meta не отдаёт `media_url`, даже владельцу. Такое видео нельзя скачать через API. Нужна выгрузка или ручная загрузка (п. 3).
7. Архивные и удалённые посты API не отдаёт (ошибка 100, subcode 33) и не различает. Даты архивации нет нигде.
8. Лимиты: Instagram Business Use Case rate limiting, окно 24 ч на пару «приложение + пользователь». Сервис шлёт запросы по одному, с паузой 0,8 с, и останавливается на ошибках лимита до следующего окна. Коды ошибок лимита (предварительно 4, 17, 32, 613) — **проверить** по документации Meta.
9. Токен: вход через Instagram даёт токен на 1 ч, его меняют на токен на 60 дней. Продление — `GET /refresh_access_token`, не раньше чем через 24 ч после выдачи. Токен, который не продлили 60 дней, умирает.
10. Ссылки `thumbnail_url` временные. Сервис сохраняет превью на диск при синхронизации.

## 7. ACRCloud (факты и решения)

1. Режим: Music Recognition API, проект Audio Fingerprinting. Фрагменты по 15 с, запрос до 5 МБ.
2. Fingerprinting плохо ловит каверы, ремиксы и музыку под голосом. Для них есть движок Cover Song (`engine_type = 2`). Он даёт `NO_MATCH` на обычных студийных записях, поэтому в v0.1 он только второй проход по желанию.
3. File Scanning не используем в v0.1: на пробном доступе его лимит кончается быстро (HTTP 400 после ~6 мин звука).
4. Отбор фрагментов: начало, середина, конец Reel (до 3 фрагментов). Если на фрагменте «Can't generate fingerprint», сервис берёт соседний участок.
5. Ключ ACRCloud — ключ студии. Сервис показывает примерный расход до запуска: число фрагментов × цена из настроек.

## 8. Правила риска

Правила лежат в файле `config/risk_rules.toml`. Студия правит списки без правки кода. Пример: `config/risk_rules.example.toml`. В оценке хранится `rules_version`.

Уровни (от худшего к лучшему):

| Уровень | Когда (правила по умолчанию) |
|---|---|
| `high` высокий | трек коммерческого лейбла; кавер известной песни; совпадение Meta с правообладателем вне списка безопасных источников |
| `medium` средний | независимый автор или неизвестный лейбл; сток без лицензии в списке `licensed_sources` |
| `unknown` неизвестно | звук недоступен и у Meta нет совпадений; распознавание с ошибкой |
| `low` низкий | только безопасные источники (Facebook Sound Collection, сток с лицензией студии); музыка не распознана |
| `no_music` без музыки | детектор музыки ничего не нашёл |
| `no_audio` без звука | в видео нет звуковой дорожки (например, Instagram удалил звук) |

Порядок расчёта:
1. Ручная отметка человека («подтверждаю риск» / «проверено, чисто») стоит выше правил. Автоматическая оценка всё равно хранится рядом.
2. Нет звуковой дорожки → `no_audio`. Совпадения Meta показываются, уровень `no_audio`.
3. Каждый сигнал (Meta, каждый фрагмент ACRCloud) даёт свой уровень. Итог — худший уровень.
4. «Не распознано» даёт `low` с причиной «распознавание не ловит каверы и музыку под голосом — послушайте». Студия может поднять его до `unknown` в настройках.
5. Порог score ACRCloud (по умолчанию 70): ниже порога совпадение считается слабым и даёт `unknown`.

У каждой оценки есть список причин: источник (Meta / ACRCloud / человек), трек, лейбл, score, правило.

## 9. Интерфейс (v0.1)

1. Сетка 3 колонки, как в Instagram: превью и цветная метка риска.
2. Вкладки «В ленте» и «Архив». Фильтр по уровню риска.
3. Карточка поста: почему такой уровень, источник, трек, лейбл, ISRC, score, статус Meta, откуда звук, ссылка на пост, плеер (если есть локальный звук), ручная отметка с комментарием, «Убрано в архив» вручную.
4. Кнопка «Актуализировать» (сверка с Meta), правила защиты — п. 10.
5. Языки DE / EN / RU, немецкий по умолчанию. Тексты — файлы `app/web/i18n/*.json`.
6. Экспорт CSV для юриста: пост, дата, уровень, причины, ручная отметка, дата пропажи из ленты.
7. В подвале каждой страницы — пометка «не юридическая консультация».

## 10. Кнопка «Актуализировать»: правила защиты

Сервис сверяет текущий список постов Meta с базой:
- пост пропал из списка → `missing` (вкладка «Архив») с датой проверки;
- пост снова в списке → `in_feed`.

Сервис **ничего не меняет**, если:
1. ответ Meta неполный (ошибка на любой странице, оборван `paging.next`);
2. у любого полученного поста нет `permalink`;
3. пропало больше 25 % ленты. Тогда сервис показывает список и ждёт подтверждения человека. Порог — в настройках.

Каждый прогон пишется в `sync_run` с итогом.

## 11. Мастер настройки

Шаги (экран за экраном, с картинками-подсказками):
1. Пароль входа в интерфейс.
2. Проверка аккаунта: Instagram — профессиональный (business или creator).
3. Создание своего приложения Meta: продукт «Instagram», вход через Instagram, право `instagram_business_basic`. Точные названия кнопок в кабинете Meta — **проверить** при первой установке, для мастера нужны скриншоты. Для своего аккаунта хватает Standard Access, проверка Meta (App Review) не нужна.
4. Аккаунт студии — в роли Instagram Tester приложения (если приложение в режиме разработки). Принять приглашение в Instagram.
5. Токен: «Generate token» в кабинете приложения (токен на 60 дней). Вставить в мастер. Сервис проверяет `GET /me` и пробует поле `copyright_check_information`.
6. Ключ ACRCloud: регион, access key, secret, тип проекта Audio Fingerprinting. Сервис делает пробный запрос на тестовом звуке.
7. Первая синхронизация и оценка расхода ACRCloud.

**Открытый вопрос № 2.** Продлевается ли через `refresh_access_token` токен, созданный кнопкой в кабинете приложения. Если да — v0.1 обходится без OAuth-перенаправления. OAuth требует публичный HTTPS-адрес, а у сервиса на ноутбуке или NAS студии его нет.

Сервис продлевает токен сам раз в 30 дней и предупреждает за 7 дней до конца срока.

## 12. Безопасность токенов

1. Токен Instagram и ключ ACRCloud хранятся в SQLite в зашифрованном виде (Fernet). Ключ шифрования — переменная `APP_SECRET_KEY`. Если она пустая, сервис при первом запуске создаёт ключ в `data/secret.key` (права 600). Ключ не входит в образ и в git.
2. Токены не пишутся в логи, в ответы API и в экспорт. Логгер маскирует строки, похожие на токен. httpx пишет полный URL с `access_token` в лог уровня INFO: логгер httpx ставим на WARNING.
3. Интерфейс по умолчанию слушает только `127.0.0.1`. Доступ из сети — через обратный прокси студии с HTTPS.
4. Вход по паролю (bcrypt), защита от CSRF у форм, сессия в cookie `HttpOnly`, `SameSite=Strict`.
5. Клиент Meta в коде разрешает только метод GET; попытка другого метода — ошибка. Это проверяет тест.
6. Права Meta — только `instagram_business_basic`.

## 13. DSGVO

1. Self-host: студия — единственный ответственный за обработку (Verantwortlicher). Автор open-source кода данные не получает и не является обработчиком (Auftragsverarbeiter).
2. Данные: свои посты студии, превью, короткая выдержка подписи. На видео бывают клиенты: превью и звук хранятся только у студии.
3. Комментарии, подписчики и личные сообщения сервис не читает.
4. Наружу уходят только фрагменты звука в ACRCloud. В них бывают голоса. **Проверить:** регион обработки ACRCloud (есть eu-west-1), договор DPA, передача в третьи страны. В README — пункт для реестра обработки студии.
5. Сервис не шлёт телеметрию и не обращается к серверам автора.
6. Фрагменты звука удаляются после распознавания. Полный звук выгрузки хранится, пока студия его не удалит (кнопка «Удалить звук»).
7. Удаление установки: `docker compose down` и удаление папки `data/`.

## 14. Что не входит в v0.1

- Stories, Highlights, фото и карусели.
- Чужие аккаунты и Business Discovery.
- Автоматическое удаление или архивация постов.
- Несколько аккаунтов, общий хостинг, платёжная часть.

## 16. Открытые вопросы

1. Отдаёт ли `graph.instagram.com` поле `copyright_check_information` (п. 6.3).
2. Продлевается ли токен из кабинета приложения (п. 11).
3. ACRCloud: цена за 1 000 запросов на тарифе студии, DPA, регион.
4. Нужен ли сигнал Meta через Facebook Login как запасной путь (требует страницу Facebook).
5. Точность сопоставления файлов выгрузки с постами (дата и длительность).
6. Откуда сигнал «без музыки» (`no_music`). Детектор музыки был в File Scanning, а v0.1 его не использует. Варианты: свой простой детектор или уровень `no_music` только по ручной отметке.
7. Коды ошибок лимита Meta и названия кнопок в кабинете Meta (п. 6.8, п. 11.3).
